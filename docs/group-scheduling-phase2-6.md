## データと権限

- `0017_group_scheduling.sql` は0016までを前提に、新規日程調整、参加対象、候補、投票を追加する。既存の募集には現在の管理者と状態を追加し、作成者IDとリアクション履歴を残す。確定共有予定は日程調整IDに一意に関連付ける。
- ○と、本人が最終確認した△だけを確定参加者にできる。×、未回答、退出済みメンバーは参加させない。最低人数・全員参加条件、現在の予定競合を確定直前に再検証する。期限後は投票できないが、管理者は既存回答を確定できる。
- 空き時間のランキングは30分刻み。既存予定、仮予定、同期未確認を分け、同期未確認を空き確定として数えない。同一入力では日付・開始時刻で安定した順序を返す。
- 募集と日程調整は元の作成者と現在の管理者を分ける。退出時は進行中のものを終了するか現行メンバーに引き継ぐ。操作と退出は一つのD1 batchで行い、最後の整合性アサーションに失敗したら全体を巻き戻す。最後の1人や管理方法のない独立した仮予定の退出は拒否する。
- 退出者の参加対象、投票、通知、Push、共有リマインドへのアクセスを現行メンバーIDで区切る。再参加後の新しいメンバーIDに旧権限を移さない。0014a・0015は変更しない。
- 日程調整のアプリ内通知は汎用文言だけを保存し、Push登録がなくても残る。Pushは既存の購読とキュー、Cronを使う。通知履歴には個人予定のタイトル・メモ、シフトの勤務先・給与を保存しない。

## API（すべて認証済みPOST、`groupId` が必要）

| 経路 | 主な用途 |
| --- | --- |
| `/api/shared/availability/search` | 共通空き時間と上位5件の順位付け。`minimumParticipants` は任意。 |
| `/api/groups/schedules/list`, `/get` | 本人が管理または参加対象である日程調整。集計と未回答を表示。 |
| `/api/groups/schedules/create`, `/update`, `/cancel` | 作成、タイトル・説明・期限編集、中止。作成には `clientRequestId` が必要。 |
| `/api/groups/schedules/options/add`, `/replace`, `/cancel` | 候補の追加・変更・取り消し。追加・変更は `clientRequestId` で重複を防ぐ。 |
| `/api/groups/schedules/vote`, `/vote/confirm-maybe` | ○・△・×の変更と、△回答者本人による最終確認。 |
| `/api/groups/schedules/confirm` | `optionId` と確定参加者を指定。競合する仮予定には明示確認が必要。 |
| `/api/groups/leave/options`, `/leave` | 退出前の進行中件数・引き継ぎ先を取得。`exitChoice` は `close` または `transfer`。 |

`create` の `sourceWishId` は任意。既存の「行きたい」は日程調整にコピーせず保持し、元の募集を `converted` として追加反応・編集を止める。確定後も履歴と仮予定の行を保持し、旧仮予定は `cancelled_at` でカレンダーから除外する。

## Frontend操作

グループカレンダーの「共通空き時間を探す」でランキングを見て候補から日程調整を開始できる。「日程調整・投票を見る」から作成、回答変更、△の最終確認、候補変更、参加者確認、確定、中止ができる。「遊びたい日」の管理者はそのカードから日程調整を開始できる。退出時に進行中のものがあれば、終了と現行メンバーへの引き継ぎを明示的に選ぶ。

## ローカル検証と公開時の注意

- VitestのD1で0017を0016の次に適用し、既存募集の管理者補完と `PRAGMA foreign_key_check`、確定・二重作成・退出・再参加を検証する。既存の0011はローカルmigration一覧にも含めない。
- 公開時は本番journalとD1 IDを再確認し、0017だけを対象とする専用設定を作る。通常のmigration一括適用で0011を巻き込まない。0017適用前にバックアップと復旧手順を検証し、旧Workerとの重複配信期間の動作を再リハーサルする。
- 0017適用後に新Worker、最後にFrontendを公開する。新Workerは0017の列・表を必要とする。旧Workerは新しい中止行を認識せず、切替中に古い表示を返す可能性があるため、本番切替検証が必要。
- 本番のmigration、Worker、Vercel、Push送信はこの開発作業では行わない。実機iPhone Safariのモーダル操作・通知リンク・背景復帰は公開前に確認する。
